## User-visible behavior

- F8 uses the existing F7 row hover, click, wheel and input arbitration. Scalar
  editing also accepts wheel adjustments, click to apply and Back/outside to
  cancel. Seven centered tabs fit their labels: System, Boosters, Cheats, Arena+,
  Input, Dev, Reforge. Scout retains its configuration keys under Dev.
- System offers independent voice, battle-sound and movie-audio language choices.
  Each offers game default, English or Japanese and requires a restart. Text and
  subtitle language are not changed by these selectors.
- Input opens native glass choice windows for keyboard shortcuts, gamepad
  shortcuts, controller selection and button mapping. New action shortcuts start
  unassigned. Existing F7, F8 and Ctrl+Shift+K defaults remain editable; Insert is
  the F8 fallback. Reserved OS/native keys and duplicate assignments are rejected.
- Controller input supports XInput and Steam Input, automatic selection or Pad
  1–4. Ten digital buttons can be permuted; choosing an occupied destination swaps
  the pair. Axes and triggers keep their native values. Shortcut chords can include
  triggers, require at least two controls, commit on release and are consumed before
  the game receives them. The opening chord cannot immediately select a menu row.
- Bindable actions include both mod menus, existing native F1–F5 actions, the game
  menu, SpeedHack, Sensor/AP, window/performance/camera controls and window refresh.
  The native game menu owns the title-return confirmation. There is no forced
  game-over, zero-HP reset or duplicate Cheats implementation.
- Idle cursor hiding now runs even without new mouse messages. It restores on
  movement, focus change or disable and preserves a foreign cursor replacement.
  Wine cannot intercept a Super key already consumed by the host compositor; F8
  reports this platform limit rather than claiming effective blocking.

## S.I.N. persistence and scripts

Claim → saved models were not always hydrated. Evidence → `F7_InstallHooks`
previously loaded `f7_inlive.json` only for flag/difficulty admission. A SIN-only
or saved-OFF configuration could therefore retain defaults. The load now precedes
runtime admission; loading preferences grants no writer authority. The source
regression is included in F7's 3,619 assertions. Confidence: high for this code
path. Conflict: no save-click event was found in the supplied session, so this does
not prove exactly which action the user performed. Next: save, restart and read back
the same seed/distribution in game.

The private exporter compiles **47 compatible AI profiles for ten Macalania
species**, covering eight curated curse types. Woods now includes Chimera. It uses
the existing Editor compiler and validator; clean monster inputs and all non-AI
content remain unchanged. The pack is 130,692 bytes, SHA-256
`F92F103E46459CFC8A1D0D845898A6D3BE2483E9650AC11A7C288140F5FD2DFF`.
`tools/sin_profiles/README.md` documents reproducible export and hash generation.
Generated bytecode stays private; the source admission header contains hashes.

The native script registration consumer is RVA `0x397A50` (VA `0x797A50`),
`int __cdecl(channel, name, AI*)`, admitted only for channel 1 and caller return
RVA `0x38417C`. Its normalized 75-byte signature is FNV-1a
`295F0925E21F0F41`. The supported executable profile is also checked. The pending
native actor is matched against the exact original AI pointer and monster ID.
Only a frozen, current natural-battle request on its owner thread may substitute
the argument. The actor's whole-file and AI ownership fields are not rewritten.

Six custom command rows (267–272, 92 bytes each) must match their exact hashes in
the current native command table at RVA `0xD2A934`. Native missing-index fallback
to row zero is explicitly rejected. Once-only curses use dedicated private
storage; the real native allocation calculator verifies the extension. Immutable
AI views and the registration trampoline are retained for process lifetime.

Successful registration publishes a bit for that actor/generation. The existing
Difficulty writer applies S.I.N. stat scaling only to those admitted actors.
Missing pack, dependencies or identity leaves the original script and stats.
No second HP writer or old external disk materializer was enabled. First-time
enablement may require saving and restarting to admit the script hook. Growth and
extra reward mechanics remain explicitly identified as previews.

## FMV acceleration

`Boosters → SpeedHack FMV acceleration` is OFF by default and restart-required.
When enabled, the existing SpeedHack selection requests 1×/2×/4×/8× movie speed;
the old native/global route is neutral while the movie bridge owns the rate.
The OSD distinguishes armed from applied. Focus loss, disable and stop request 1×.

The verified consumer is RVA `0x6284A0`, `bool __thiscall(player, tex1, tex2, tex3)`.
The normalized 81-byte signature is FNV-1a `C5248B6A135E2A6A`; caller return RVAs
are `0x2DAF6A` and `0x2D78F5`. The receiver must be the current global movie's
embedded player, with active/ready state, bounded decoded queue and neutral native
boost. Frame bursts use available queue depth and retain the last valid frame on
partial/EOF results. Native timestamps advance through the original frame count.

Only the movie's current FMOD channel is accelerated. The adapter checks sound
identity and frequency ownership, supports a lower rate when the requested rate
is rejected and restores its own rate without overwriting a foreign adjustment.
An epoch prevents a stale render callback from reapplying speed after focus loss.
**Audio pitch rises with speed.** This is not pitch-preserving time stretching.

RT1 executes the exact native timestamp getter and callback ABI with controlled
frame/audio sinks. A separate fixture uses the shipped `fmodex.dll` with NOSOUND
output and proves frequency, sound identity and restoration. Neither fixture is
an end-to-end video decode or audible synchronization test. Player acceptance of
a complete FMV, subtitles, ending transition and focus restoration remains pending.

## Provenance and scope reconciliation

Reference: [official UnX feature documentation](https://wiki.special-k.info/SpecialK/Custom/UnX).
Local source: `Kaldaien/UnX`, commit
`faae4359bc5f39872536654fda0f4562dd8b7d36`, `UnX/language.cpp` and input/window
behavior. These source files identify GPL-3.0-or-later; the Hooks repository is
GPL-3.0-or-later. The language path behavior was adapted on 2026-09-23. No UnX or
Special K menu/DLL is loaded by the new adapters.

The linked [FFX-Cutscene-Skip-Turbo](https://github.com/wwwroot/FFX-Cutscene-Skip-Turbo)
at `19f78a5f95e09399925932b222aa716b317f44d2` is MIT-licensed and explicitly excludes
FMVs. It was investigated as a behavior reference; the movie bridge above was
derived from the supported FFX executable, not presented as an upstream FMV port.

Existing AP, Sensor, Seymour, Cheats, speed controls and native F1–F5 consumers are
reused. The supported executable already declares DPI awareness. Window refresh
uses a temporary client resize and exact placement restoration, with no global
desktop change; it is not a guarantee that every loading hang is recoverable.
DirectInput-to-XInput translation is also disabled as broken in the inspected UnX
source. This package exposes XInput/Steam Input rather than a fictitious DirectInput
backend. Texture/icon replacement, HDR/flip presentation, VSync changes and unsafe
quicksave/forced-close shortcuts are outside this package. Native confirmations
remain available through the game's menu.
